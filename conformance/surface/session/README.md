# Structured Session conformance fixtures

These fixtures exercise the durable `nopal.session/v2` and `nopal.session/v3` endpoint contracts documented in [`docs/surface/session.md`](../../../docs/surface/session.md).
Prompt submission keeps `nopal.session.command/v1`.
V2 endpoints use only `nopal.session.event/v2`.
V3 endpoints preserve exact persisted v2 envelopes and append `nopal.session.event/v3` envelopes on the same stream.

- `valid-prompt-command.jsonl` contains one prompt with additive envelope and payload fields.
- `invalid-prompt-text.jsonl` proves an empty or whitespace-only prompt cannot enter the durable command path.
- `valid-events.jsonl` contains all four legacy v1 event variants used as migration inputs.
- `invalid-command-kind.jsonl` proves unsupported command versions fail closed.
- `foreign-session-event.jsonl` is a structurally valid legacy event that fails expected-context validation.
- `cold-replay-v2.jsonl` contains a cold subscribe, a three-event durable replay, additive fields, and its exact completion head.
- `resume-replay-v2.jsonl` resumes after a verified cursor and reports one replayed event at the same snapshot head.
- `duplicate-overlap-v2.jsonl` contains an exact duplicate delivery that a verified timeline treats as a no-op.
- `cursor-conflict-v2.jsonl` reuses one cursor for conflicting event content and must freeze ingestion at the verified prefix.
- `foreign-durable-event-v2.jsonl` is structurally valid v2 data for another Session and must fail context binding.
- `feed-errors-v1.jsonl` covers a fatal contextual history gap, a retryable pre-context availability failure, a retryable replay-buffer overflow, and a command identity conflict.
- `malformed-controls-v1.jsonl` covers a missing required nullable cursor, an excessive page bound, an impossible replay head, and partial error context.
- `identity-bounds-v1.jsonl` freezes the shared 4096 UTF-8 byte identity boundary with one accepted command identity and one rejected identity.
- `mixed-replay-v3.jsonl` contains a production-algorithm stream and cursor chain with an exact persisted v2 prefix followed by typed v3 command start and finish events.
- `resume-mixed-v3.jsonl` resumes from that exact verified v2 head and replays only the v3 suffix through the unchanged mixed-stream head.

The stream identity and four cursors in `mixed-replay-v3.jsonl` are generated by the production durable-log canonical JSON and SHA-256 algorithm for `plot-fixture` and `session-fixture`.
The Rust v3 parser consumes the fixture as a mixed typed feed.
The TypeScript durable-log regression hydrates its exact v2 prefix and must generate a v3 suffix that deep-compares with the same checked-in fixture.

The parser tests generate a line of 1 MiB plus one byte rather than checking a megabyte-sized fixture into source control.
Every v2 parser must reject that line before attempting JSON parsing.
The shared command identity validators must accept the at-limit fixture and reject its one-byte-larger neighbor before journal or timeline access.

Run all checked consumer tests with:

```sh
cargo test -p nopal-feed-client session::tests
```
